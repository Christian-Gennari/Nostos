Part of [#747](https://github.com/Christian-Gennari/Nostos/issues/747).
Checkpoint: **tooling verified; audiobook feasibility remains blocked before scoring**.

## Actions and observations

- Downloaded Gutenberg EPUBs 46 (*A Christmas Carol*) and 1342 (*Pride and Prejudice*),
  and their LibriVox tracks from the recordings linked below. Original source URLs
  and SHA-256 hashes are in `candidate-manifest.json`. No audio or EPUB binaries
  are committed.
- The canonical Archive.org redirect returned HTTP 500 on Carol's third track;
  its metadata-provided storage mirror succeeded. All six approved tracks were
  subsequently downloaded. This was a source-download retry, not a paid model call.
- Ran existing `EpubBookTextExtractor`: Carol 759 blocks / 159,482 text characters;
  Pride 2,207 blocks / 710,834 characters. The hashes and normalized source locators
  survive CLI serialization and matching.
- Generated all 32 candidate WAV clips (mono, 16 kHz, PCM16): each of 16 endpoints
  has a 10-second and 20-second window ending at the same track timestamp.
  Six positive and two intro **candidates** per book await independent listening.
- Built a whole-book lexical matcher consuming no expected chapter/location hints,
  retaining the existing EPUB locator contract. Exact unique phrases precede
  tolerant token edit matching. Weak and ambiguous matches return no location.
- Fixed a test's mistaken global-offset expectation: extracted blocks have a
  separator. Added a regression for a token crossing source segments; the endpoint
  now maps to the segment containing its last character.
- Offline synthetic calibration passed 10 cases with score threshold 0.85,
  alternative-location margin 0.12, minimum 8 words and last 24 transcript words.
  `offline-calibration.json` records actual scores and settings/binary hashes.
  This does not establish audiobook quality.
- Text-only real-EPUB smoke examples located Carol's opening in block 33 and
  Pride's opening in block 28, both confidence 1.0. `extraction-smoke.json`
  contains source locators. These inputs were extracted text, not transcription.
- Added offline replay, per-resource endpoint error, latency, false accepts,
  rejections, unique positive-position count, and required manual acceptance
  receipts. Missing cases cannot pass the 11/12 gate; manual review cannot erase
  an incorrect result against frozen ground truth.

## Stopping point and decision

This session's audio loading returned `audio content omitted because you do not
support audio input`. Browser playback alone cannot supply an observed transcript.
I did not replace independent listening with an ASR-derived answer key. Expected
passages and intro rejections remain null, and candidate timestamps may need moving.

**Zero model requests and zero scored audiobook cases.** There is no model quality
ranking, false-accept rate, latency comparison, or successful-handoff cost yet.
Gateway configuration and economic receipts belong in the private Cloud issue.
The dedicated experiment key was stopped and revoked without spending.

Recommendation: independently inspect and label these 32 candidates, replacing
any non-intro or unsuitable position before freezing; then run the approved fixed
comparison. Do not begin reader integration. SelfHosted Settings, hosted reader
browser acceptance, PDF, persistent anchors, other languages, and text → audio
remain later checkpoints. Leave #747 open.
