# Calibre test fixture

A small Calibre library used by the Calibre import tests (issue #1527). It is
**not** anyone's real library and contains no purchased or in-copyright text.

## How it was made

`build_fixture.py` generates `library/` from scratch:

- `metadata.db` is created from Calibre's own schema, copied verbatim into
  `calibre_schema.sql` from Calibre's source
  ([`resources/metadata_sqlite.sql`](https://github.com/kovidgoyal/calibre),
  GPL-3.0-or-later). The script registers the few SQL functions Calibre itself
  provides (`title_sort`, `uuid4`, `concat`, `sortconcat`,
  `books_list_filter`) so Calibre's own triggers run, then inserts the rows
  with fixed timestamps and UUIDs. `PRAGMA user_version` is 28 and the
  application id is `0x63616c69`, as Calibre writes them.
- Each book sits in the path Calibre would give it:
  `Author/Title (id)/Title - Author.epub`.
- EPUB and PDF files are tiny, valid files generated by the script from a
  single public-domain sentence per book. The MP3 is 0.6 seconds of generated
  silence. The covers are 4×6 solid-colour JPEGs. The MOBI/AZW3 files are
  marker bytes: Nostos never reads those formats, and the review screen is
  meant to list them as skipped.
- `#read` (bool), `#date_read` (datetime), `#genre` (text) and `#pages` (int)
  are the custom columns. Only the first two are common columns the importer
  maps; the other two are there to prove they are reported as skipped.

`calibredb` was not installed on the machine that built this fixture
(`which calibredb` found nothing), so the database is written by the script
from Calibre's schema rather than by Calibre itself. If you have `calibredb`,
you can verify the fixture by adding the generated book folders to a fresh
Calibre library; the fixture is not regenerated that way automatically.

Rebuild it with:

```bash
cd Nostos.Backend.Tests/Fixtures/calibre
python3 build_fixture.py --force
```

The script is deterministic for a given Python/SQLite version: fixed book
ids, timestamps, UUIDs and ZIP member dates. `metadata.db` may still differ by
a few bytes between SQLite builds because of page layout.

For a measurement library of 300 books:

```bash
python3 build_fixture.py --synthetic 300 --out /tmp/calibre-300
```

## The books

| Id | Title | Author(s) | Formats | Read |
| --- | --- | --- | --- | --- |
| 1 | Pride and Prejudice | Jane Austen | EPUB, PDF | 2020-05-01 |
| 2 | Alice's Adventures in Wonderland | Lewis Carroll | EPUB, MOBI | read flag, no date |
| 3 | The Time Machine | H. G. Wells | EPUB | no |
| 4 | The Gilded Age | Mark Twain & Charles Dudley Warner | EPUB, MP3 | 2021-01-02 |
| 5 | The Art of War | Sun Tzu | MOBI, AZW3 (unsupported) | no |
| 6 | The Yellow Wallpaper | Charlotte Perkins Gilman | EPUB (recorded, file missing) | no |
| 7 | The Adventure of the Blue Carbuncle | Arthur Conan Doyle | EPUB | no |
| 8 | The King in Yellow | Robert W. Chambers | EPUB, PDF | no |

The metadata (`title`, `authors`, `series`, `series_index`, `tags`,
`publisher`, `identifiers`, `rating`, `comments`, `has_cover`) follows each
work's public-domain publication details where known. Where an ISBN is
present it is a valid ISBN-13 checksum; the edition numbers are illustrative.
